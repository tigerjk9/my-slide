# share-deck

이 폴더는 HTML 슬라이드를 `build.js`로 묶어 한 파일짜리 발표 페이지 `index.html`을 만드는 구조다. 슬라이드는 1280×720 캔버스에 그리고, 뷰어가 화면 크기에 맞춰 통째로 축소·확대한다. 뷰어에는 좌우 화살표, [목차], [QR](지금 페이지 주소), [전체화면]이 달려 있다.

요청: $ARGUMENTS

## 폴더 구조

| 경로 | 역할 | 손대는 때 |
| --- | --- | --- |
| `deck.config.json` | 제목·부제·발표자·날짜. 슬라이드의 `{{title}}` 같은 자리에 들어간다 | 제목·발표자·날짜가 바뀔 때 |
| `slides/NN-이름.html` | 슬라이드 한 장. 두 자리 번호가 순서다 | 내용을 쓰거나 고칠 때 |
| `assets/slide-theme.css` | 색·글꼴·공통 구성 요소 | 새 공통 요소가 필요할 때만 |
| `viewer/template.html`, `viewer.css`, `viewer.js` | 발표 페이지 틀·스타일·동작 | 뷰어 기능을 바꿀 때만 |
| `vendor/qrcode.min.js` | QR 라이브러리(qrcode-generator 1.4.4, MIT) | 건드리지 않는다 |
| `build.js` | 위 재료를 모아 `index.html` 생성 | 묶는 규칙이 바뀔 때만 |
| `index.html` | 생성물. 직접 고치지 않는다(다음 빌드가 덮어쓴다) | 절대 직접 편집 금지 |

스킬 번들: `assets/slide.template.html`(새 슬라이드 뼈대), `assets/examples/`(검증된 슬라이드 5장 사본), `scripts/verify.js`(스크린샷·동작·넘침 검사).

## 할 일 고르기

- 새 주제로 발표자료를 만든다 → A
- 슬라이드를 고치거나 끼워 넣거나 순서를 바꾼다 → B
- 제목·부제·발표자·날짜만 바꾼다 → C
- 다시 묶거나 점검만 한다 → D

어느 경우든 끝은 같다: `node build.js` → `scripts/verify.js` → 스크린샷을 직접 보고 → 보고.

## A. 새 발표자료 만들기

1. 주제, 대상(학부모·학생·교사·동료), 분량을 요청에서 읽는다. 분량이 없으면 5장. 대상이 말투와 정보 밀도를 정한다. 학부모 설명회라면 합니다체, 한 장에 핵심 3~4개.
2. `deck.config.json`을 채운다. 발표자 이름을 모르면 "담임 교사"처럼 역할로 두고 보고 때 알린다. 날짜를 모르면 요청에 나온 날짜, 없으면 오늘 날짜를 쓴다.
3. 기존 `slides/*.html`이 있고 다른 주제라면 지우지 말고 `slides/archive/<날짜>-<옛 제목>/`로 옮긴다. `build.js`는 `slides/` 바로 아래의 `NN-이름.html`만 모으므로 하위 폴더는 빌드에 섞이지 않는다.
4. 장별 메시지를 한 문장씩 먼저 정한다. 5장 기본 흐름은 표지 → 왜(이유·배경) → 무엇을(계획) → 함께(요청·역할) → 마무리(약속·질문). 주제에 맞게 바꿔도 되지만 각 장이 한 가지 주장만 하도록 한다.
5. 슬라이드를 쓴다. `assets/slide.template.html`을 복사해 시작하고, 아래 규약과 디자인 규칙을 따른다. 레이아웃은 `assets/examples/`의 다섯 장을 먼저 읽고 장마다 다르게 고른다.
6. 빌드·검증·보고(아래 공통 절차).

## B. 슬라이드 고치기·추가·순서 바꾸기

- 순서는 파일 이름의 번호가 전부다. 중간에 끼워 넣으면 뒤 번호를 밀어서 다시 붙인다(03 → 04). 번호가 겹치면 빌드가 경고를 낸다.
- 삭제는 파일을 `slides/archive/`로 옮긴다.
- 제목이 바뀌면 `data-title`과 `<title>`을 같이 고친다. 목차는 `data-title`을 읽는다.
- 고친 뒤 반드시 다시 묶는다. `index.html`만 보고 고치면 다음 빌드에서 사라진다.

## C. 설정만 바꾸기

`deck.config.json`의 네 키(`title`, `subtitle`, `presenter`, `date`)를 고치고 다시 묶는다. 키가 비면 빌드가 실패하도록 되어 있다.

## D. 다시 묶기·점검

공통 절차만 수행한다. 검증에서 문제가 나오면 원인 파일(슬라이드 또는 viewer/)을 고치고 다시 묶는다.

## 슬라이드 규약 (build.js가 기대하는 것)

- 파일 이름: `NN-이름.html`. 두 자리 번호, 하이픈, 한글 이름 가능. 예: `03-우리-반-실천-계획.html`
- 완전한 HTML 문서로 쓴다. 단독으로 열어도 보이도록 `<body class="slide-preview">`와 `<link rel="stylesheet" href="../assets/slide-theme.css">`, Google Fonts 링크를 둔다.
- 본문은 `<section class="slide 고유클래스" data-title="목차에 보일 제목">` 하나. 빌드는 `<body>` 안쪽 전체와 `<style>`을 가져가고 나머지는 버린다.
- 슬라이드별 스타일은 `<style>` 안에 쓰되 반드시 고유 클래스로 범위를 한정한다(`.plan .rhythm { }`). 모든 슬라이드 스타일이 `index.html` 한곳에 모이므로 범위 없는 선택자는 다른 장을 망가뜨린다.
- 설정값은 `{{title}}` `{{subtitle}}` `{{presenter}}` `{{date}}`로 넣는다. 표지와 마무리에 발표자·날짜를, 본문 장에는 왼쪽 아래 `<p class="running">{{title}} · {{subtitle}}</p>`를 둔다. 설정에 없는 자리표시자는 빌드가 경고한다.
- 크기는 1280×720 고정. 안쪽 여백은 테마가 `72px 88px 64px`로 잡는다. 러닝 헤드가 아래 40px에 있으므로 본문은 y 640 이전에 끝나야 한다.
- 이미지 파일을 쓰지 않는다. 장식은 인라인 SVG로 그린다. `index.html` 하나로 완결되어야 메일·USB로도 전달된다.

## 디자인 규칙

- 색과 글꼴은 `assets/slide-theme.css`의 변수만 쓴다: 종이(`--paper`), 먹(`--ink`), 짙은 초록(`--forest`), 붉은 흙(`--clay`), 꿀색(`--honey`). 새 색을 만들지 않는다. 제목은 Noto Serif KR 900, 본문은 Noto Sans KR.
- 공통 요소: `.kicker`(작은 붉은 제목) → `.title`(큰 제목) → `.lead`(한 줄 설명) 순서가 머리 부분의 기본형이다. 표지·마무리는 `.shelf`(책꽂이 선)와 `.spines`(책등 SVG)로 짝을 맞춘다.
- 장마다 구성을 다르게 한다. 예시 다섯 장이 각각 표지(책꽂이), 2단 편집형(번호 목록 + 아래 큰 숫자), 타임라인 띠(4열), 해 주세요/피해 주세요(비대칭 2단), 마무리(2단 + 책꽂이)다. 같은 크기 카드 격자 반복, 모든 것을 가운데 정렬, 그라데이션 글자, 둥근 상자에 그림자는 쓰지 않는다.
- 분량은 제목 1~2줄, 항목 3~4개, 항목당 한두 문장. 글이 넘치면 글을 줄이지 글자 크기를 먼저 줄이지 않는다.
- 한국어 줄바꿈은 테마가 `word-break: keep-all`로 처리한다. 숫자와 단위("약 120시간")가 줄 끝에서 갈라지면 `<br>`로 끊을 자리를 정해 준다.

## 글쓰기 규칙

- 글을 쓰기 전에 `~/.claude/codex-port/korean-writing.md`를 읽고 적용한다. 번역투, 상투어, 대구 반복, 과장을 뺀다.
- 높임은 대상에 맞춰 한 가지로 통일한다. 학부모·외부 청중은 합니다체.
- 수치는 산수로 확인되는 것만 쓴다(하루 20분 × 365일 ≈ 120시간). 출처 없는 통계나 연구 인용은 넣지 않는다.
- 요일·시각·절차 같은 학급 세부는 일반적인 예시로 쓰고, 보고에서 예시임을 밝혀 사용자가 고치게 한다.

## 빌드와 검증 (공통 절차)

```
node build.js
node .claude/skills/share-deck/scripts/verify.js --out <스크래치패드>/share-deck-check
```

- `build.js`는 슬라이드 목록과 경고를 출력한다. 경고(번호 중복, 남은 자리표시자, `class="slide"` 없음)가 있으면 고치고 다시 묶는다.
- `verify.js`는 슬라이드별 `slide-N.png`와 `toc.png`, `qr.png`, `fullscreen.png`, `mobile.png`를 찍고, 화살표·Home/End·해시 진입·목차·QR·전체화면·자동 숨김을 점검하며, 슬라이드 밖으로 나간 글 요소를 `overflow`로 보고한다. Playwright를 못 찾으면 헤드리스 Chrome으로 스크린샷만 찍는다.
- PNG를 Read 도구로 직접 본다. 겹침, 잘림, 한쪽으로 쏠린 빈 공간, 줄 끝에서 갈라진 숫자를 눈으로 잡는다. 스크립트는 바깥으로 넘친 것만 잡고 안에서 겹친 것은 못 본다.
- Chrome 확장(claude-in-chrome)이 연결되어 있으면 실제 브라우저에서 한 번 더 열어 봐도 좋다. 연결이 안 되어 있으면 스크립트 결과로 충분하다.

## 보고

- 만든 파일과 `index.html` 여는 법, 조작법(화살표·Home/End·F·스와이프)을 짧게 적는다.
- 반드시 알리는 것: 로컬 파일(file://)로 열면 QR이 휴대전화에서 열리지 않으니 웹에 올린 뒤 그 주소로 쓰라는 점, 글꼴은 Google Fonts라 오프라인이면 맑은 고딕으로 대체된다는 점, 역할로 둔 발표자 이름과 예시로 쓴 세부 내용.
- 검증 결과는 사실대로 적는다. 스크립트를 못 돌렸으면 못 돌렸다고 쓴다.
